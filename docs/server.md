# Сервер и CI/CD

API владельца: `https://45.11.229.77:8443`. Сертификат Let’s Encrypt выпущен на IP,
продлевается автоматически; после продления nginx перечитывает сертификат.
Порт 8443 выделен отдельно, поскольку 80/443 заняты другими сайтами.

## Подключение расширения

Обнови расширение до 0.7.0. Открой **Настройки → Синхронизация с сервером**, введи
адрес и личный ключ, нажми **Подключить и передать историю** и разреши соединение.
В Firefox отдельно запрашивается согласие на передачу активности и ключа авторизации.
Ключ передаётся только выбранному серверу по HTTPS, хранится в `storage.local`, не
попадает в GET_STATE, content script, JSON-экспорт или репозиторий. Это пароль ко всей
истории; не публикуй его и не выдавай другим пользователям продукта.

При подключении отправляется текущая локальная история и загружаются последние
серверные результаты. После теста или импорта синхронизация планируется примерно
через 30 секунд; повторная проверка — каждые 5 минут, пока работает браузер.
Есть кнопка немедленной синхронизации и видимый статус ошибки. Отключение стирает
ключ из расширения. Серверная история при этом остаётся.

Для восстановления в другом браузере введи тот же адрес и ключ. Без сети доступна
локальная история: максимум 160 сессий / 6 МБ. Если долго оставаться офлайн и превысить
этот лимит, вытесненные несинхронизированные записи не попадут на сервер. Сервер
хранит все полученные сессии, но возвращает только последние 160 / 6 МБ; статистика
панели и её JSON-экспорт пока строятся по этому локальному окну. Настройки и 40 планов
упражнений остаются локальными; метаданные уже пройденных тренировок синхронизируются.

## Устройство

- Node.js 24 в `/opt/keyloom-runtime`, отдельный системный пользователь `keyloom`.
- `server/app.mjs`: HTTP только на loopback, авторизация Bearer, ограничение тела,
  валидация через общий core, удаление неизвестных полей, транзакции SQLite.
- `/var/lib/keyloom/history.sqlite`: база, WAL и SHM рядом. Новые ID вставляются,
  повторная доставка ничего не меняет; результаты считаются неизменяемыми.
- `/etc/keyloom.env`: путь базы и секрет, доступен root. Не копировать в Git.
- `keyloom.service`: перезапуск при сбое, права на запись только в каталог данных.
- `keyloom-backup.timer`: ежедневная согласованная SQLite-копия, последние 7 дней
  в `/var/lib/keyloom/backups`. Копии на том же диске не защищают от потери сервера;
  внешний backup пока не настроен.

Контракт: `POST /v1/sync`, JSON `{version:1,sessions:[...]}`, заголовок
`Authorization: Bearer <ключ>`. Ответ: `{version:1,sessions:[...],total:N}`.
`GET /health` публично возвращает только `{ok:true}`. API не предоставляет публичную
регистрацию: это личное хранилище владельца, а не многопользовательское облако.

## Деплой

Workflow **CI** сначала запускает тесты и сборки Chrome/Firefox в четырёх окружениях.
При push в `main` после всех проверок выполняется deploy. Для первого запуска и
проверки ветки используется **Actions → CI → Run workflow**, с выбором ветки.
PR сам по себе не запускает деплой; автоматического merge нет.

GitHub Secrets: `KEYLOOM_DEPLOY_HOST`, `KEYLOOM_DEPLOY_KEY`, `KEYLOOM_KNOWN_HOSTS`.
Проверка host key включена. Root-пароль и ключ API в GitHub не передаются.
Пользователь `keyloom-deploy` может загружать релизы и через sudo перезапускать
только `keyloom`. Деплой выполняется последовательно; код размещается в
`/opt/keyloom/releases/<SHA>`, ссылка `current` переключается атомарно. Если health
не отвечает, скрипт возвращает прежний релиз. База находится вне релиза и не заменяется.
Изменения unit/nginx из `deploy/` администратор применяет отдельно: CI не имеет root-shell.

Проверки администратора:

```sh
systemctl status keyloom --no-pager
systemctl list-timers keyloom-backup.timer
curl --fail https://45.11.229.77:8443/health
systemctl start keyloom-backup.service
```

Для восстановления останови `keyloom`, сохрани текущие SQLite/WAL/SHM в отдельный
закрытый каталог, скопируй выбранный backup на место базы с владельцем `keyloom`,
убери старые WAL/SHM после сохранения и запусти сервис. Для полного удаления истории
нужно удалить также резервные копии и локальные данные браузеров; иначе следующая
синхронизация вновь загрузит локальные результаты. Публичного API удаления пока нет.

Ротация ключа: сгенерируй криптографически случайный URL-safe токен длиной ≥32,
замени `KEYLOOM_TOKEN` в закрытом `/etc/keyloom.env`, перезапусти сервис и заново
подключи свои браузеры. Старый ключ перестанет работать.

Официальная инструкция [Let’s Encrypt для IP-сертификатов](https://letsencrypt.org/2026/03/11/shorter-certs-certbot/).
