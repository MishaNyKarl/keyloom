# Публикация Keyloom в магазинах

Состояние на 15 сентября 2026: Firefox 0.8.0 отправлен в AMO с исходным архивом и примечаниями к версии. Статус: «Ожидает проверки». ID версии: 6488111, файл: 5032273. Локальная проверка и валидатор AMO: 0 ошибок и предупреждений. Исходный commit: fe9e105 в main. Заявлен Firefox desktop 142+, без Android. Архивы ранее отправленной 0.7.3 сохранены отдельно.
CI/CD сейчас обновляет личный API; он не публикует расширения в магазинах автоматически.

## Что подготовить в продукте

- Иконки расширения и магазина, скриншоты, понятное описание, контакт поддержки.
- Собственный код: All Rights Reserved, решение владельца закреплено в LICENSE.
  Лицензия vendored lz-string включена отдельно. Keyloom не официальный Monkeytype.
- Опубликовать политику приватности с контактами владельца и реальным процессом
  удаления данных. Описать наблюдаемые слова, тайминги, локальный кеш, добровольную
  передачу серверу и срок хранения резервных копий; не писать «данные никуда не отправляются».
- Решить модель синхронизации для других пользователей: собственные серверы пользователей
  либо отдельные аккаунты с изоляцией на нашем API. Текущий личный ключ владельца
  не включать в пакет и не выдавать пользователям или ревьюерам.
- Проверить установленные Chrome и Firefox: завершение/перезапуск RU/EN/quote,
  подключение и отзыв разрешений, офлайн, перенос истории, обновление без потери данных.
- Для ревью подготовить изолированный тестовый сервер/доступ с синтетической историей.

## Chrome Web Store

1. Зарегистрировать аккаунт разработчика Google и оплатить разовый регистрационный
   сбор; актуальная сумма и доступные способы оплаты указаны при регистрации.
2. Собрать Chrome-пакет: `node scripts/build.mjs chrome`; упаковать **содержимое**
   `artifacts/chrome`, чтобы manifest.json находился в корне ZIP.
3. В Developer Dashboard создать новый item и загрузить ZIP, заполнить Store listing,
   Privacy и Distribution. Указать единственную задачу расширения, объяснить `storage`,
   `alarms`, доступ к Monkeytype и optional HTTPS-host permission для выбранного сервера.
4. Добавить privacy URL, изображения, контакты и инструкции для проверки; отправить
   на ревью. После принятия публиковать версию через кабинет. ID расширения сохранять.

Официально: [регистрация](https://developer.chrome.com/docs/webstore/register),
[публикация](https://developer.chrome.com/docs/webstore/publish/).

## Firefox Add-ons (AMO)

### Подготовленные материалы

- `docs/firefox-listing.md` — описание, поля карточки, контакт и инструкции ревьюеру.
- `extension/privacy.html` — политика приватности; доступна из настроек, её текст
  нужно добавить в поле политики в AMO.
- `extension/icons/keyloom-256.png` — иконка карточки; 48/96/128 включены в расширение.
- `review/` — оригинальный читаемый исходник lz-string 1.5.0, лицензия и происхождение.
- `node scripts/prepare-firefox.mjs` — создаёт `artifacts/firefox` и отдельный
  `artifacts/firefox-source` по списку разрешённых файлов, без секретов и сервера.
- `web-ext 10.6.0 lint` включён в CI. Локальная проверка: 0 ошибок, 0 предупреждений.

PowerShell, после подготовки:

```powershell
Compress-Archive -Path artifacts/firefox/* -DestinationPath artifacts/keyloom-firefox-0.9.0.zip -Force
Compress-Archive -Path artifacts/firefox-source/* -DestinationPath artifacts/keyloom-firefox-source-0.9.0.zip -Force
```

В пакет для установки загружается первый ZIP. Второй — в поле исходников для ревью.
Перед отправкой нужны финальные скриншоты с явно обозначенными демоданными,
ручная проверка установленного подписанного релиза. Вход в AMO выполнен, карточка и политика приватности отправлены. Условия соглашения
разработчика принимает владелец аккаунта. Подписанный пакет выдаёт Mozilla.

1. Войти в Mozilla Add-on Developer Hub, выбрать Submit a New Add-on и публикацию
   на addons.mozilla.org, а не только подпись для самостоятельного распространения.
2. Собрать `node scripts/build.mjs firefox` и загрузить ZIP содержимого
   `artifacts/firefox`. Сохранить ID `keyloom@mishanykarl`.
3. Заполнить описание, категорию, лицензию, контакты, privacy policy и Notes for Reviewers
   из `docs/firefox-listing.md`.
   Если требуется исходный пакет, приложить исходники и точные команды сборки;
   не включать `artifacts`, ключи, серверные данные и профили браузеров.
4. Исправить замечания валидатора и пройти проверку. Mozilla подписывает пакет;
   временная установка через about:debugging не заменяет подпись для обычной установки.

Manifest уже содержит обязательный `websiteContent` для текста упражнения,
добровольные `websiteActivity` и `authenticationInfo` для синхронизации. Запрос
согласия вызывается при подключении сервера; desktop minimum — Firefox 142.

Официально: [загрузка дополнения](https://extensionworkshop.com/documentation/publish/submitting-an-add-on/),
[исходный код](https://extensionworkshop.com/documentation/publish/source-code-submission/),
[согласие на передачу данных](https://extensionworkshop.com/documentation/develop/firefox-builtin-data-consent/).

После первой публикации можно отдельно настроить store CD с API-ключами магазинов
в GitHub Secrets. Это другой процесс: загрузка серверного кода не заменяет ревью,
подпись и выпуск обновления расширения.
