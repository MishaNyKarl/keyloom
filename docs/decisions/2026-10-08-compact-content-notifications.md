# Короткие уведомления вместо подписки страницы на хранилище

## Контекст

Профиль Firefox, переданный владельцем, содержит примерно семь секунд записи.
В процессе Monkeytype обнаружены `ExtensionStorage.deserializeForContext`,
`ext-storage.onChanged`, сборщик циклического мусора с паузой около 1558 мс
и обходом около 4,25 млн GC-объектов. Обработчик ввода представлен единичными
сэмплами. Профиль не доказывает происхождение каждого объекта: событие хранилища
в записанном интервале следует за первой длинной паузой. Накопление объектов
за предыдущие сохранения — гипотеза, а сама доставка изменений в страницу — факт.

Content script подписывался на `storage.onChanged`, проверяя интересующие ключи
внутри callback. В Firefox изменения распаковываются до этого фильтра. Сохранение
и синхронизация заменяют массив истории и модель обучения, поэтому страница
получала ненужные oldValue/newValue этих крупных объектов.
Личный профиль не сохраняется в репозитории и не используется как фикстура.

## Решение

Подписка перенесена в background. Изменения sessions/learning сами по себе
не рассылаются. Для settings/dailies/theme читаются только настройки, планы и тема;
в страницы отправляется `KEYLOOM_STATE_CHANGED` с необязательными settings
(enabled/layout), theme и today (done/total/minutes либо null). Получатель
проверяет ID расширения, тип и форму полей. Другие данные не принимаются.

Background получает ID открытых вкладок через tabs.query({}) и отправляет сообщение
в основной фрейм. Вкладки без нашего получателя и закрытые вкладки игнорируются.
Это позволяет переживать перезапуск MV3 worker без реестра подписчиков и новых
permissions. Никакие адреса/содержимое посторонних вкладок не используются.
GET_STATE остаётся источником начального состояния, GET_TODAY_PROGRESS обновляет
счётчик при возвращении на страницу; короткие уведомления заменяют только события.

## Варианты и последствия

Фильтр внутри прежней подписки не устраняет распаковку. Опрос таймером добавил бы
работу во время печати. Реестр подписчиков в памяти терялся бы после сна worker;
постоянные порты потребовали бы отдельного восстановления соединений.
Рассылка маленьких сообщений требует операций по числу открытых вкладок, но
не передаёт историю в процесс Monkeytype. Подписки dashboard/popup остаются.

Формат данных, история и разрешения совместимы; миграция не нужна. После обновления
нужна перезагрузка всех Monkeytype-вкладок, иначе прежний content script остаётся.
Недопустимо засчитывать тест, который сам Monkeytype прервал по производительности.

## Проверка

Поведенческие node:test проверяют отсутствие storage-подписки в странице,
ограниченный payload и отсутствие чтения истории для уведомлений, несколько вкладок,
отсутствующего получателя, область storage, проверку отправителя, переключение записи
и сохранение текущего теста при обновлении прогресса/темы. Автотесты не измеряют
реальные паузы GC Firefox; нужен повторный контроль установленного расширения.
