# Команды Keyloom и клавиатурная навигация

## Контекст

Переход между заданиями не должен требовать мыши. Monkeytype сам использует
Tab/Esc для команд и перезапуска, в зависимости от quickRestart.
Проверен исходник frontend/src/ts/commandline/commandline.ts в официальном
репозитории: команды управляются внутренними списками и состоянием модалки,
публичного контракта для внешних расширений в нём нет.

## Решение

Используем отдельный локальный диалог с поиском на Alt+K и Alt+N для следующего
задания. Модуль keyboard.js общий для dashboard и content script. Команды вызывают
существующие обработчики и сообщения, без нового доступа к данным, инъекции в
основной JS-контекст сайта, патчей его меню или удалённого исполнения.
Alt-комбинации не работают во время теста, в чужих полях и модалках. Tab/Esc на
Monkeytype не перехватываем. В собственном приложении Esc доступен вне полей.

## Варианты и последствия

Вставка пункта в DOM меню Monkeytype не подключает его внутреннюю фильтрацию,
навигацию и выполнение. Патч внутренних модулей привязал бы нас к сборке сайта.
Отдельное меню требует своего сочетания, зато изолировано от обновлений меню сайта.
При появлении официального API можно добавить адаптер к тому же списку действий.

Визуальная система: верхняя навигация, открытые разделы, акцентные значения,
спокойные разделители, локальный моноширинный шрифт. layout.css задаёт композицию
поверх существующих компонентных стилей, themes.css остаётся источником палитр.
Новые пользовательские данные или миграция для этих изменений не нужны.
